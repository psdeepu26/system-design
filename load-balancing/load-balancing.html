⚖️ Load Balancing Algorithms

System Design — Like you're 5, then like you're an engineer
🧒 LIKE YOU'RE 5
Imagine a busy food court with 4 counters and 1 long queue. You need a system to decide which counter each person goes to:

🪑 Round Robin — "Next!" The host sends person #1 to Counter A, #2 to B, #3 to C, #4 to D, #5 back to A. Fair rotation, but if Counter A's cook is slow, that queue builds up.

🎯 Least Connections — Look at which counter has the shortest line right now and send the next person there. Adapts to slow cooks automatically.

⏱️ Least Response Time — Same as above, but also factor in "which counter served the last person fastest?" The food court manager keeps a stopwatch.

🔒 IP Hash — "You always go to Counter A because your birthday is in January." Same person, same counter every time — so the cook remembers your order.

The big idea: Without a good system, one counter is crushed while three are idle. A load balancer is just a smart host making sure everyone gets fed fairly.
↓ Now let's call it what it really is ↓
🔧 FOR THE ENGINEER
🔄

Round Robin

Requests distributed in circular order: A → B → C → A → B → C.

Pros: Simple, no state needed.
Cons: No awareness of server load. Bad for heterogeneous servers.

Weighted variant: Servers with more capacity get more requests (weight=3 vs weight=1).

🎯

Least Connections

Route to server with fewest active connections.

Pros: Adapts to varying request durations.
Cons: Needs connection tracking state on LB.

Nginx: upstream backend { least_conn; ... }
HAProxy: balance leastconn

⏱️

Least Response Time

Route to server with lowest avg response time + fewest active connections.

Pros: Picks both least busy AND fastest server.
Cons: Needs monitoring overhead.

HAProxy: balance first picks first available. AWS ALB uses least outstanding requests (LOR).

🧮

IP Hash / Sticky Sessions

Hash client IP → same client → same server.

hash = crc32(client_ip) % server_count

Use case: Session persistence without cookies. Great for in-memory sessions.
Downside: Uneven distribution if client IPs cluster (corporate NAT).

Nginx: ip_hash; directive.

📊

L4 vs L7 Load Balancing

Layer 4 (TCP): NAT-based. Fast, sees IP+port only.
Layer 7 (HTTP): Reads headers, cookies, paths. Can do intelligent routing (/api/* → backend A, /static/* → backend B).

Health checks: LB pings servers periodically. Unhealthy servers removed from pool.

🏭

Real-World Tools

NGINX: Layer 7, great for HTTP APIs
HAProxy: TCP + HTTP, battle-tested
AWS ALB: Managed L7, path/host-based routing
K8s Service: iptables-based round robin by default
Envoy: Modern proxy, advanced LB + circuit breaking

⚡

Micro-action: Check what LB algorithm your current infrastructure uses. Run kubectl describe svc <your-service> — K8s default is round robin via iptables/IPVS.
